      02
      
02 Method
A repeatable testing process.

      
Tools find signals. Methodology turns signals into findings that can be explained, reproduced, fixed and retested. Static analysis (SAST) reviews the code; dynamic testing (DAST) probes the running application — together they cover what the code says and what the application does.

      

        

          1
          
Recon
Define scope, passively map exposed assets, understand technologies and identify likely entry points before testing deeper.
ReconForgeOSINTNmap

          
$ scope --confirm example-app
✓ authorized scope loaded
$ recon --passive example.com
→ 14 hosts · 6 technologies mapped

        

        

          2
          
Scan
Review exposed services and configurations, then prioritize the signals that deserve manual investigation.
NmapOWASP ZAP · passiveNucleiOpenText Fortify

          
$ nmap -sV -T3 example.com
443/tcp open  https
$ nuclei -u https://example.com
→ 3 signals queued for validation

        

        

          3
          
Enumerate
Trace routes, identities and API boundaries to understand where trust and sensitive data move.
Burp SuitePostmanffufWireshark

          
$ ffuf -u https://example.com/FUZZ -w common.txt
→ /api  /admin  /static
$ map --roles --objects
→ 4 roles · 11 object types

        

        

          4
          
Exploit
Validate suspected weaknesses safely within scope, confirm impact and remove false positives before anything is reported.
OWASP ZAP · authorized activeSQLMapFridaMetasploit

          
$ validate --finding F-02 --safe
→ BOLA confirmed · minimal impact
$ evidence --capture F-02
✓ request / response saved

        

        

          5
          
Report
Developer-focused findings: reproducible proof, risk-based prioritization, clear fixes — and a retest to close the loop.
EvidenceSeverityRetest

          
$ report --format dev
✓ 3 findings · fixes attached
$ retest --all
→ 3/3 patched · status: closed
